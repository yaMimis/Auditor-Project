## 1. Crédito e risco

| Termo                                      | O que é                                                                                                | No projeto                                                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Bondora**                          | Plataforma estoniana de empréstimos entre pessoas.                                                     | Fonte dos dados: 179.235 contratos de 2009 a 2021 (corte em 20/07/2021), usados no lugar de uma base brasileira.                   |
| **Carteira**                         | Conjunto de contratos de crédito de uma instituição.                                                 | O modelo pontua a carteira de 2017 a 2021, que é 82,6% da base.                                                                   |
| **Cliente** (`cliente_id`)         | Pessoa que toma o crédito e pode ter vários contratos.                                                | 85.087 clientes, dos quais 36.185 têm mais de um contrato. Identificado por `cliente_id`, pseudonimizado.                       |
| **Default** (inadimplência)         | Deixar de pagar o contrato.                                                                             | `data_default` preenchida. O Bondora registra a data quando o atraso passa de 60 dias, segundo o dicionário.                    |
| **Inadimplente**                     | Contrato que entrou em default.                                                                         | É o alvo do modelo (`inadimplente = 1`): 56,0% da base de modelagem.                                                            |
| **PD**                               | Chance de o cliente deixar de pagar.                                                                    | Probabilidade de default em qualquer momento do contrato, calculada pelo modelo e comparada com a `pd_bondora`.                  |
| **LGD**                              | Parte do valor devido que se perde quando há default, ou seja, o que não é recuperado.               | A recuperação dos contratos que atrasaram entra na LGD. O valor vem da `lgd_bondora` ou é calculado com defaults antigos.     |
| **EAD**                              | Quanto o cliente devia na hora do default.                                                              | Colunas `ead1` e `ead2` (lista negra).                                                                                         |
| **Perda esperada**                   | Perda média que o credor espera ter: PD × LGD × EAD.                                                 | Entra no cálculo do juro justo.                                                                                                   |
| **Rating**                           | Nota de risco que o Bondora dá ao contrato: AA (menor risco), A, B, C, D, E, F e HR.                   | É saída do modelo do Bondora, então fica na lista negra. Só descreve na EDA.                                                   |
| **Score de bureau**                  | Nota de crédito calculada por uma empresa de análise de crédito.                                     | `score_ee_mini`, `score_fi_asiakastieto`, `score_es_equifax` e `score_es_microl`. Fora do próprio país, vale "sem_info". |
| **Reestruturado**                    | Contrato cujas condições foram renegociadas depois da concessão.                                     | 7.941 contratos, com 76% de default. Ficam no modelo e saem só da auditoria de preço.                                            |
| **Contrato encerrado**               | Contrato que já foi pago (`Repaid`) ou que entrou em default.                                        | Só eles entram na base de modelagem.                                                                                              |
| **Coorte**                           | Grupo de contratos concedidos no mesmo período.                                                        | Usamos o ano da concessão.                                                                                                        |
| **Coorte madura**                    | Coorte antiga o bastante para o desfecho já ter aparecido.                                             | Concessões de 2009 a 2016.                                                                                                        |
| **Base de modelagem**                | Contratos usados para treinar e testar o modelo.                                                        | 29.916 contratos (2009–2016, encerrados, sem a Eslováquia), na view `vw_base_modelagem`.                                       |
| **Faixa de risco**                   | Grupo de contratos com PD parecida.                                                                     | Devolvida pelo `prever()` junto com a PD.                                                                                        |
| **Crédito pessoal não consignado** | Empréstimo pessoal sem desconto em folha de pagamento, em geral com juros mais altos que o consignado. | Modalidade da referência de mercado do BC (série 20742).                                                                         |

## 2. Preço e mercado

| Termo                                                 | O que é                                                                                                          | No projeto                                                                                                                                         |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Juro cobrado**                                | Taxa que o contrato realmente cobra, em % ao ano.                                                                 | Coluna `juro_aa`. É o preço auditado e fica na lista negra do modelo de risco.                                                                 |
| **Juro justo**                                  | Taxa que cobre o custo do dinheiro, a perda esperada, os custos e a margem.                                       | Calculado por fluxo de caixa e comparado com o cobrado.                                                                                            |
| **Margem de incerteza**                         | Faixa em volta do juro justo que reflete o erro do modelo.                                                        | O contrato só é marcado como fora do preço quando a diferença passa da margem.                                                                 |
| **Dentro, acima ou abaixo do justo**            | Classificação do contrato conforme o juro cobrado e o justo, levando em conta a margem.                         | Resultado da tarefa "Comparar o juro cobrado com o justo" do BPMN.                                                                                 |
| **Fluxo de caixa**                              | Sequência de entradas e saídas de dinheiro de um contrato: parcelas e perdas.                                   | Base do cálculo do juro justo, com a tabela de amortização simulada.                                                                            |
| **Custo do dinheiro**                           | Quanto custa ao credor obter o dinheiro que empresta.                                                             | Euribor do mês da concessão.                                                                                                                     |
| **Spread**                                      | Diferença entre o juro cobrado e o custo do dinheiro.                                                            | Usado como dado de apoio na comparação com o mercado brasileiro.                                                                                 |
| **Euribor**                                     | Taxa média a que bancos europeus emprestam euros entre si.                                                       | Séries de 12 meses (principal) e de 3 meses (sensibilidade), em média mensal, do Portal de dados do BCE. Valores negativos viram zero no preço. |
| **Piso em zero**                                | Regra que troca uma taxa negativa por zero.                                                                       | Aplicada à Euribor no cálculo do preço.                                                                                                         |
| **Selic**                                       | Taxa básica de juros do Brasil.                                                                                  | Série 4189 do BC, anualizada, usada no cenário "modo Brasil".                                                                                    |
| **Base 252**                                    | Convenção brasileira de contar 252 dias úteis no ano para anualizar taxas.                                     | Explica o nome da série 4189.                                                                                                                     |
| **SGS**                                         | Sistema do Banco Central que reúne séries temporais.                                                            | Origem das séries 4189 (Selic) e 20742 (crédito pessoal).                                                                                        |
| **Referência de mercado do BC** (série 20742) | Taxa média das novas operações de crédito pessoal não consignado de pessoas físicas, mensal, desde 03/2011, em % ao ano efetiva. | Só contexto no painel e no parecer, numa frase fixa escrita pelo código (o LLM não recebe o número), com o valor convertido para nominal. Não calibra o preço nem entra no modelo. |
| **CET**                                         | Custo total do crédito para o cliente, com juros, tarifas, tributos e demais encargos, em % ao ano.              | As normas do Banco Central sobre CET fazem parte da base do RAG.                                                                                   |
| **Modo Brasil**                                 | Aplicar regras e cenários brasileiros a dados europeus.                                                          | O parecer analisa "se este contrato fosse de um banco brasileiro". A Selic só aparece no cenário.                                                |
| **% a.a. e % a.m.** | Taxa ao ano e taxa ao mês. | Os juros do projeto estão em % ao ano, como taxa nominal (a mensal é a anual ÷ 12). |
| **Taxa nominal** | Taxa anual dividida em partes iguais por mês, sem contar juros sobre juros: a mensal é a anual ÷ 12. | É a convenção do Bondora (`juro_aa`): reproduz a parcela dos contratos. |
| **Taxa efetiva** | Taxa que já conta os juros sobre juros: (1 + mensal)^12 − 1. | É a do BC (série 20742) e a que o CDC (art. 52) manda informar. Converte-se para nominal com 12 × [(1 + efetiva)^(1/12) − 1]. |
| **ROI**                                         | Ganho em relação ao que foi investido.                                                                          | Calculado em euros na carteira real.                                                                                                               |
| **Backtest**                                    | Teste de uma regra com dados do passado, usando o desfecho que realmente aconteceu.                               | Os contratos marcados como "abaixo do justo" deram mais prejuízo? Se sim, a auditoria funciona.                                                   |
| **Retorno realizado** | Quanto voltou, em euros, de um contrato em relação ao que foi emprestado: (principal e juros recebidos − valor concedido) ÷ valor concedido. | View `vw_retorno_realizado`. As recuperações já estão dentro dos pagamentos, e o cálculo não desconta o tempo. |
| **Coroa estoniana (EEK)**                       | Moeda da Estônia até 31/12/2010, a 15,6466 coroas por euro.                                                     | Confirmado nos dados: a renda e os passivos de 2009–2010 estão em EEK, enquanto os valores dos empréstimos já foram convertidos para euros.    |

## 3. Dados e banco

| Termo                                   | O que é                                                                                                          | No projeto                                                                                                           |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **CSV**                           | Arquivo de tabela em formato de texto.                                                                            | `LoanData_Bondora.csv` e as séries de taxas ficam em `data/raw/`, fora do Git.                                  |
| **Tabela e view**                 | A tabela guarda dados no banco. A view é uma consulta salva que se usa como se fosse uma tabela.                 | Tabelas `emprestimo`, `cliente` e `historico_credito`. Views `vw_base_modelagem` e `vw_custo_do_dinheiro`. |
| **PostgreSQL**                    | Banco de dados relacional de código aberto.                                                                      | Roda no Docker, com a extensão pgvector.                                                                            |
| **SQL**                           | Linguagem para consultar e criar estruturas em bancos relacionais.                                                | Os esquemas ficam em `db/`.                                                                                        |
| **pgvector**                      | Extensão do PostgreSQL que guarda e busca vetores.                                                               | Guarda os embeddings das normas, no mesmo banco.                                                                     |
| **Lista negra de colunas**        | Colunas que nunca podem ser variável do modelo: pós-concessão ou saídas do Bondora.                           | 26 colunas (`COLUNAS_LISTA_NEGRA`), com teste automático.                                                         |
| **Só auditoria**                 | Colunas usadas apenas para auditar a equidade, nunca para decidir.                                                | `genero`, `idade`, `estado_civil` e `n_dependentes`.                                                         |
| **Indisponíveis depois de 2017** | Colunas que somem ou vêm zeradas a partir de 2017–2018.                                                         | 7 colunas (`COLUNAS_INDISPONIVEIS_RECENTES`).                                                                      |
| **Valor sentinela**               | Valor especial que quer dizer "sem informação".                                                                 | O Bondora usa -1 em colunas de código, e a carga troca por vazio.                                                   |
| **Zero no lugar de vazio**        | Campo sem informação gravado como 0.                                                                            | `divida_renda`, `caixa_livre` e `renda_empregador_principal` a partir de 2018.                                 |
| **Valor extremo** (outlier)       | Valor muito distante dos demais. Pode ser erro ou legítimo.                                                      | Juros acima de 100% na Espanha e na Finlândia são legítimos.                                                      |
| **Dicionário de dados**          | Documento que explica o significado de cada coluna.                                                               | Public Reports do Bondora.                                                                                           |
| **Pseudonimização**             | Trocar o identificador por um código que só se liga à pessoa com uma chave guardada à parte.                  | O `UserName` vira `cliente_id`.                                                                                  |
| **HMAC**                          | Hash com chave secreta, que gera um código fixo para cada entrada.                                               | Gera o `cliente_id`, com a chave `CLIENTE_ID_SAL` fora do Git.                                                   |
| **SHA-256**                       | Impressão digital de um arquivo: muda por completo se um caractere mudar.                                        | Confere se todos usam o mesmo `LoanData_Bondora.csv`.                                                              |
| **Pandera**                       | Biblioteca de Python que confere se uma tabela segue regras.                                                      | Valida as tabelas em `src/dados/validacao.py`.                                                                     |
| **Esquema de validação**        | Lista das regras que cada coluna precisa cumprir.                                                                 | Um esquema por tabela.                                                                                               |
| **Erro e alerta**                 | O erro quebra o contrato dos dados e falha o teste. O alerta é uma ocorrência conhecida, registrada sem falhar. | 0 erros e 12 alertas no relatório de qualidade.                                                                     |
| **EDA**                           | Olhar os dados com tabelas e gráficos antes de modelar.                                                          | `notebooks/dados/01_eda.ipynb` e as figuras de `docs/figuras/`.                                                  |
| **Relatório de qualidade**       | Resumo dos problemas encontrados nos dados.                                                                       | `docs/qualidade_dados.md`.                                                                                         |
| **Datasheet dos dados**           | Ficha que descreve origem, composição, usos e limites de um conjunto de dados.                                  | Entrega da frente de Dados.                                                                                          |
| **Só inclusão** (append-only) | Tabela em que só se acrescentam linhas: nenhuma é alterada nem apagada. | Vale para `decisao_analista`. Para corrigir, registra-se outra decisão. |
| **Gatilho** (trigger) | Regra do banco que roda sozinha quando uma linha é inserida, alterada ou apagada. | Define a data e a origem das decisões e bloqueia alterações. |

## 4. Modelagem

| Termo                                       | O que é                                                                                                                 | No projeto                                                                    |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| **Variável** (feature)               | Informação que o modelo usa para prever.                                                                               | 23 variáveis na versão v3.                                                  |
| **Alvo** (target)                     | O que o modelo tenta prever.                                                                                             | `inadimplente`.                                                             |
| **Baseline**                          | Modelo simples usado como referência para comparar.                                                                     | Regressão logística.                                                        |
| **Regressão logística**             | Modelo que combina as variáveis para estimar uma probabilidade.                                                         | Baseline.                                                                     |
| **XGBoost**                           | Modelo que soma muitas árvores de decisão pequenas, cada uma corrigindo os erros da anterior.                          | Modelo principal, regularizado e calibrado.                                   |
| **Regularização**                   | Penalidade que impede o modelo de ficar complexo demais.                                                                 | Aplicada ao XGBoost.                                                          |
| **Early stopping**                    | Parar o treino quando a validação deixa de melhorar.                                                                   | Aplicado ao XGBoost.                                                          |
| **Sobreajuste** (overfitting)         | Quando o modelo decora o treino e erra nos dados novos.                                                                  | Evitado com validação e teste fora do tempo.                                |
| **Treino, validação e teste**       | Treino ajusta o modelo, validação escolhe parâmetros e teste mede o resultado final.                                  | Treino e validação em 2009–2015 (20.011 contratos). Teste em 2016 (7.311). |
| **GroupKFold**                        | Validação cruzada que mantém todos os contratos de um mesmo grupo do mesmo lado.                                      | Grupos por `cliente_id`.                                                    |
| **Divisão temporal**                 | Treinar no passado e testar no futuro.                                                                                   | Teste em 2016, sem clientes que já estavam no treino.                        |
| **Vazamento de dados** (data leakage) | O modelo usar informação que só existiria depois da decisão.                                                         | Evitado com a lista negra e um teste automático.                             |
| **Calibração**                      | Fazer a probabilidade prevista bater com a frequência observada.                                                        | Isotônica ou sigmoide, ajustada sem usar 2016.                               |
| **Curva de calibração**             | Gráfico que compara a probabilidade prevista com a frequência real.                                                    | Principal métrica do preço.                                                 |
| **AUC**                               | Mede quão bem o modelo ordena os contratos: 0,5 é como jogar moeda e 1 é ordenar perfeitamente.                       | Métrica de ordenação.                                                      |
| **KS**                                | Maior distância entre a distribuição dos escores dos bons e a dos maus pagadores.                                     | Métrica de ordenação.                                                      |
| **Brier**                             | Erro médio quadrático entre a probabilidade prevista e o resultado (0 ou 1). Quanto menor, melhor.                     | Mede a qualidade da probabilidade.                                            |
| **PSI**                               | Mede quanto a distribuição de uma variável mudou entre dois períodos. Acima de 0,25 costuma indicar mudança grande. | Compara anos.                                                                 |
| **SHAP**                              | Método que mostra quanto cada variável empurrou a previsão para cima ou para baixo.                                   | Dá os motivos do `prever()` e alimenta o template de reserva.              |
| **Segmentação** (K-Means)           | Agrupar contratos parecidos sem usar o alvo.                                                                             | Não entra no modelo de risco: descreve a carteira por perfil.                |
| **Intervalo de confiança**           | Faixa em que o valor verdadeiro provavelmente está.                                                                     | Acompanha a diferença residual na equidade.                                  |
| **Diferença residual**               | Diferença de juro que sobra entre grupos depois de controlar por risco, ano, país, valor e prazo.                      | Base da auditoria de equidade. É um indício, não uma conclusão.           |
| **Análise de sensibilidade**         | Ver quanto o resultado muda quando uma premissa muda.                                                                    | Euribor de 12 e de 3 meses, por exemplo.                                      |

## 5. IA generativa

| Termo                             | O que é                                                                                     | No projeto                                                                                                            |
| --------------------------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **IA generativa**           | IA que produz conteúdo novo, como texto.                                                    | Gera o parecer.                                                                                                       |
| **LLM**                     | Modelo de IA treinado em muito texto, que escreve e responde em linguagem natural.           | Escreve o parecer com a PD, o juro e as normas já calculados.                                                        |
| **Prompt**                  | Instrução dada ao LLM.                                                                     | Versionados e avaliados em 20 casos.                                                                                  |
| **RAG**                     | Técnica que busca trechos de documentos e os entrega ao LLM para responder com base neles.  | Busca nas normas de LGPD, CDC e Banco Central.                                                                        |
| **Embedding**               | Representação de um texto como lista de números, em que textos parecidos ficam próximos. | Guardados no pgvector, em modelo multilíngue.                                                                        |
| **LangChain**               | Biblioteca para montar aplicações com LLM em etapas (cadeias).                             | Cadeia RAG do parecer.                                                                                                |
| **Fine-tuning**             | Retreinar um LLM com exemplos próprios.                                                     | O projeto usa RAG, que permite citar a norma e atualizá-la sem retreinar. A justificativa completa fica com a Maria. |
| **Alucinação**            | O LLM inventar uma informação que parece verdadeira.                                       | Mitigada com saída em JSON, checagem dos números e template de reserva.                                             |
| **Parecer**                 | Texto que explica ao analista o resultado da auditoria de um contrato.                       | Fala em indício e ponto de atenção, nunca em ilegalidade.                                                          |
| **Saída estruturada**      | Pedir ao LLM um formato fixo, como JSON, em vez de texto livre.                              | Resumo, pontos de atenção, recomendação, fontes e números citados.                                               |
| **Checagem dos números**   | Conferir por código se cada número do parecer é igual ao da API.                          | Se divergir, entra o template de reserva.                                                                             |
| **Template de reserva**     | Texto montado por código, sem LLM.                                                          | Usado quando os números divergem ou a API falha.                                                                     |
| **Avaliação em 20 casos** | Teste do parecer em 20 contratos.                                                            | Mede recuperação, fidelidade, citação e alucinação.                                                             |
| **Agentic coding**          | Programar dirigindo agentes de IA que leem o código e propõem mudanças.                   | O README registra como cada frente usou.                                                                              |

## 6. Equidade, ética e legislação

| Termo                                         | O que é                                                                                       | No projeto                                                                        |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **Equidade** (fairness)                 | Tratar de forma justa pessoas com o mesmo risco, sem diferença por características pessoais. | Auditoria de preço por gênero, idade e país.                                   |
| **Viés**                               | Tendência sistemática que favorece ou prejudica um grupo.                                    | Pode vir dos dados, do modelo ou do preço.                                       |
| **Discriminação**                     | Tratamento desigual injustificado.                                                             | O parecer não usa a palavra: fala em indício.                                   |
| **Proxy**                               | Variável que carrega a mesma informação de outra, mesmo sem a usar diretamente.             | Tirar gênero e idade do modelo não elimina proxies.                             |
| **Indício**                            | Sinal que pede investigação, sem ser conclusão.                                             | Palavra obrigatória no parecer e nos resultados de equidade.                     |
| **Direito de revisão** (LGPD, art. 20) | O titular pode pedir revisão de decisões tomadas só por tratamento automatizado.            | Por isso o sistema nunca decide sozinho.                                          |
| **LGPD**                                | Lei brasileira de proteção de dados pessoais (Lei 13.709/2018).                              | Base das normas do RAG e das regras de privacidade.                               |
| **CDC**                                 | Lei brasileira de proteção ao consumidor (Lei 8.078/1990).                                   | Base das normas do RAG.                                                           |
| **Compliance**                          | Área que cuida de cumprir leis e normas internas.                                             | O analista pode encaminhar um caso.                                               |
| **Governança**                         | Regras e responsabilidades para usar a IA com segurança.                                      | Seção própria da apresentação.                                               |
| **Decisão humana**                     | A decisão final é de uma pessoa, não do sistema.                                            | O analista mantém o preço, recomenda ajustar a taxa ou encaminha ao compliance. |
| **Fora da auditoria** | Contrato que não entra na comparação de preço da auditoria. | Os reestruturados: ficam no modelo, mas saem da auditoria de preço (coluna `fora_da_auditoria`). |
| **Trilha de auditoria** | Registro de quem decidiu o quê, quando e com base em quê, que não pode ser alterado depois. | Tabela `decisao_analista`: cada decisão do analista, com o parecer, a justificativa e os números do momento. |

## 7. Processo e engenharia

| Termo                                      | O que é                                                                                                                                                    | No projeto                                                                 |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **BPMN**                             | Notação padrão para desenhar processos de negócio.                                                                                                      | Arquivos em `docs/bpmn/`.                                                |
| **Pool e raia** (lane)               | O pool é o participante do processo. A raia divide o pool por responsável.                                                                                | Raias: sistema, motor de IA e analista.                                    |
| **Gateway**                          | Ponto em que o fluxo se divide ou se junta. O exclusivo (X) segue só um caminho.                                                                           | "Juro fora da margem de incerteza?"                                        |
| **Evento**                           | Algo que acontece: início ou fim do processo.                                                                                                              | "Contrato recebido para auditoria" começa o fluxo.                        |
| **Tarefa de serviço e de usuário** | A de serviço é feita pelo sistema. A de usuário é feita por uma pessoa.                                                                                 | "Revisar o parecer e as métricas" é do analista.                         |
| **Docker e Docker Compose**          | Docker empacota um programa com o que ele precisa. O Compose sobe vários de uma vez.                                                                       | Sobe o PostgreSQL com pgvector.                                            |
| **API**                              | Forma de um programa pedir serviços a outro.                                                                                                               | A API recebe o contrato e devolve PD, faixa, juro justo, margem e motivos. |
| **FastAPI**                          | Biblioteca de Python para criar APIs.                                                                                                                       | Serviço do `prever()`.                                                  |
| **Streamlit**                        | Biblioteca de Python para criar telas web de dados.                                                                                                         | Painel do analista.                                                        |
| **JSON**                             | Formato de texto para trocar dados estruturados.                                                                                                            | Contrato do `prever()` e do parecer.                                     |
| **pydantic**                         | Biblioteca que valida dados em Python.                                                                                                                      | Valida os formatos da API e do parecer.                                    |
| **Git, branch, commit e PR**         | Git guarda o histórico do código. Branch é uma linha de trabalho. Commit é uma versão salva. O Pull Request pede revisão antes de juntar à `main`. | Cada frente trabalha em branch própria.                                   |
| **CI e GitHub Actions**              | Robô que roda os testes a cada envio de código.                                                                                                           | Instala as dependências e roda o pytest.                                  |
| **pytest**                           | Biblioteca de Python para escrever e rodar testes.                                                                                                          | Testes em `tests/`.                                                      |
| **.env**                             | Arquivo local com configurações e segredos.                                                                                                               | Guarda `DATABASE_URL` e `CLIENTE_ID_SAL`. Nunca vai ao Git.            |
| **Notebook**                         | Documento que mistura código, resultados e texto.                                                                                                          | `notebooks/dados/` e `notebooks/modelos/`.                             |
| **BFSI**                             | Setor de bancos, serviços financeiros e seguros.                                                                                                           | Segmento do bootcamp.                                                      |
| **TCS**                              | Empresa de consultoria e tecnologia da banca.                                                                                                               | Avalia a apresentação final.                                             |
